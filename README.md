# MGTS Object ImageReviewer

Система мониторинга городской инфраструктуры МГТС с компьютерным зрением: по изображениям с камер служебных автомобилей находит объекты инфраструктуры (кабельные колодцы, опоры) и определяет их состояние: **Исправен / Не исправен / Требует проверки**.

## Как работает

```
кадр → YOLO11s (детектор: колодец, опора) → вырезка объекта → YOLO11s-cls (ok / damaged) → рамки + статус
```

Модель разделена на два этапа, потому что неисправных примеров мало. Детектор учится только находить объекты, а классификатор только оценивает состояние. Каждая модель решает более простую задачу.

Режимы работы (по схеме проекта):

| Режим | Что делает |
|---|---|
| Изображение | Анализ одного фото |
| Видео | Кадр каждые N секунд (по умолчанию 5, настраивается) |
| Трансляция | Кадр из потока (веб-камера / RTSP) каждые N секунд |

Статус «Требует проверки» ставится, когда классификатор не уверен: вероятность поломки находится между порогами `damaged_thr` и `ok_thr`.

**Плохой снимок.** Перед нейросетью кадр проходит проверку качества: резкость (дисперсия Лапласиана), яркость и разрешение.

| Ситуация | Ответ |
|---|---|
| Файл не читается | HTTP 400 «Не удалось прочитать изображение» |
| Снимок плохой, объекты не найдены | «Плохое качество снимка» + причина («снимок размыт», «слишком темно»…) и просьба переснять |
| Снимок плохой, объекты найдены | Результат возвращается, но «Исправен» понижается до «Требует проверки» с пометкой о качестве |
| Снимок хороший, объектов нет | «Объекты не найдены» |

Пороги задаются в начале `src/inspector.py`.

## Структура

```
configs/datasets.yaml        список открытых датасетов Roboflow
configs/classes.yaml         единая схема классов и ключевые слова для их сведения
scripts/01_download_datasets.py   скачать и объединить открытые датасеты
scripts/02_autolabel.py           авторазметка своих фото (Grounding DINO)
scripts/03_train_detector.py      обучение детектора YOLO11
scripts/04_train_classifier.py    обучение классификатора состояния
src/inspector.py             пайплайн: изображение / видео / трансляция
src/cli.py                   запуск из консоли
app/api.py                   HTTP API нейросети (FastAPI)
Appilcation/                 бэкенд ASP.NET Core 10 + PostgreSQL (Broker)
models/                      сюда сохраняются detector.pt и classifier.pt
```

## Быстрый старт

### 0. Окружение

Нужен Python 3.10+ и видеокарта NVIDIA (на CPU тоже работает, но обучение займёт очень много времени).

```bash
python -m venv .venv
.venv\Scripts\activate           # Windows
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
```

### 1. Данные

**Открытые датасеты.** Понадобится бесплатный ключ: https://app.roboflow.com/settings/api

```bash
set ROBOFLOW_API_KEY=ваш_ключ      # Windows (Linux: export ...)
python scripts/01_download_datasets.py
```

Скрипт скачивает датасеты из `configs/datasets.yaml`, переводит их классы в схему `manhole` / `pole` и вырезает объекты с метками состояния (`broken`, `not broken` и т.п.) для классификатора.

**Наш датасет** (фото исправных и неисправных объектов без рамок):

```
data/raw/own/ok/*.jpg
data/raw/own/damaged/*.jpg
```

```bash
python scripts/02_autolabel.py
```

Grounding DINO находит объекты по текстовому запросу и сохраняет рамки. **Обязательно пролистайте превью в `data/autolabel_preview`** и удалите ошибочные примеры. Метка состояния ставится на всё фото, поэтому если на снимке несколько объектов, а сломан только один, вырезки из `data/cls` нужно проверить вручную.

### 2. Обучение

```bash
python scripts/03_train_detector.py        # ~1–2 ч на RTX 4070 Laptop, → models/detector.pt
python scripts/04_train_classifier.py      # ~10–20 мин, → models/classifier.pt
```

Если не хватает видеопамяти, уменьшите `--batch`. Для большей точности используйте `--model yolo11m.pt --batch 8`. Графики обучения сохраняются в `runs/`.

Без своей видеокарты можно обучать в Google Colab (GPU T4): готовый блокнот лежит в `notebooks/train_colab.ipynb` (File → Upload notebook).

### 3. Запуск

```bash
python -m src.cli image photo.jpg
python -m src.cli video ride.mp4 --interval 5
python -m src.cli stream 0 --interval 5          # веб-камера
```

Картинки с рамками и `report.json` сохраняются в `outputs/<имя>/`.

API для сайта:

```bash
uvicorn app.api:app --port 8000      # документация: http://localhost:8000/docs
```

| Метод | Вход | Выход |
|---|---|---|
| `POST /analyze/image` | файл изображения | `status`, `objects[]`, `image_b64` (картинка с рамками) |
| `POST /analyze/video` | видеофайл, `interval` | `frames[]`, `need_attention` |
| `WS /analyze/stream` | JPEG-кадры от клиента | JSON по каждому кадру |

Пример ответа:

```json
{
  "status": "Не исправен",
  "status_code": "damaged",
  "needs_attention": true,
  "message": null,
  "quality": {"ok": true, "issues": [], "sharpness": 412.5, "brightness": 118.3},
  "objects": [
    {"object_type": "manhole", "object_name": "Колодец", "det_conf": 0.91,
     "bbox": [412, 530, 590, 640], "status": "Не исправен", "status_code": "damaged",
     "is_damaged": true, "damage_prob": 0.87}
  ],
  "image_b64": "..."
}
```

## Результаты первого обучения

Colab, GPU T4. Детектор YOLO11s обучался 25 эпох, классификатор YOLO11s-cls 10 эпох на 6 открытых датасетах Roboflow: 3100 изображений, 565 исправных и 950 неисправных люков.

| Модель | Метрика |
|---|---|
| Детектор (колодец, опора) | mAP50 = 0.68, mAP50-95 = 0.40 |
| Классификатор состояния люков | top-1 accuracy = 0.90 |

Ограничение: в открытых данных метки состояния есть только у люков, поэтому состояние опор пока не оценивается (статус «Не определено»). Чтобы оценивать опоры, нужно добавить свой датасет через `02_autolabel.py`.

## Бэкенд (Appilcation/)

ASP.NET Core 10 + PostgreSQL. Принимает фото и видео, ставит их в очередь, фоновый обработчик отправляет файлы в нейросеть (`app/api.py`), результат и кадры с рамками сохраняются.

```
uvicorn app.api:app --port 8000      # нейросеть
cd Appilcation/Broker && dotnet run  # бэкенд, swagger: http://localhost:5226/swagger
```

| Метод | Что делает |
|---|---|
| `POST /api/files/upload` (form-data `formFile`) | Загрузка фото/видео → `202` + id |
| `GET /api/files/upload/{id}` | Статус (`Pending` / `Processing` / `Ok` / `HasProblems` / `Failed`), объекты, ссылки на кадры |
| `GET /api/files/{id}/frames/{n}` | Кадр с рамками |
| `POST /api/stream/frame` | Трансляция: один кадр, ответ сразу |
| `GET /api/model/health` | Доступна ли нейросеть |

## Метрики

- Детектор: mAP50 и mAP50-95 (печатаются после обучения).
- Классификатор: accuracy и, главное, **полнота по классу `damaged`**: пропустить сломанный люк хуже, чем лишний раз отправить бригаду на проверку.

## Планы

- Привязка к GPS по времени кадра и карта объектов.
- Объединение повторов одного объекта из соседних кадров (трекинг или кластеризация по координатам).
- Сравнение с RF-DETR.
